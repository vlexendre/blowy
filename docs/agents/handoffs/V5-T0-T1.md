## Décisions
- Compatibilité consommateurs (aucun fichier `apps/**` touché) : `ERROR_CODES`/`ErrorCode` gardés (V4, dépréciés) car `Record<ErrorCode,…>` dans l'API ; nouveau `API_ERROR_CODES`/`ApiErrorCode` (+ `GONE`). Idem `STAFF_ROLES` (V4) / `STAFF_ROLES_V5` (+ `ops`) à cause de `ROLE_PERMISSIONS: Record<StaffRole,…>`. `EntitlementKeyV5` séparé. `PREMIUM_SPECIES`/`FREE_SPECIES`/`INTENTIONS` dépréciés, non modifiés.
- Moteur V4 : `@blowy/pet-engine/v4` ; la racine réexporte V4 (déprécié) + V5. Aucun fichier V4 supprimé.
- Tuning : sections V5 avec `.default()` → une version publiée V4 reste lisible (défauts V5 appliqués). Fiabilité V5 sous `reliability.v5`, notifications sous `notifications.v5`, composition sous `outings.composition`.
- `OutingView` et vues V5 en `.strict()` : un champ non prévu (fuite) fait échouer la validation (utile à J18). Test qui balaie les clés interdites (intentions, genre, votes d'autrui…).
- Composition : couples d'échanges = groupes voisins d'une même classe (complexité O(passes·g·36) annoncée par la spec) ; meilleur échange par passe.
- Pet V5 : `PetStateV5` ajoute `memoriesByKind` (déblocages « n-ième ») ; le fuseau est passé à `poseForV5`, pas stocké. Stades V5 recalibrés : jeune 100, adulte 600 (`memories.stageThresholds`), sans toucher `petXp` V4.
- Contenus : variables ajoutées `prenom`, `jour`, `heure`, `quartier` ; variantes discrètes limitées à `{heure}`. `CONTENT_VERSION = content-2026.12.0`.
