# Langues et textes

Minimoa parle français, anglais, espagnol, portugais et néerlandais, selon la langue du téléphone : français si le
téléphone est en français, sinon la langue proposée la plus proche, anglais en repli (spéc V7 §23). Le français est la
langue d'écriture : chaque texte s'écrit d'abord en français, les autres langues suivent par clés.

## Le principe (une minute)

Un **dictionnaire** déclare ses textes dans les cinq langues :

```ts
export const moi = messages({
  fr: { title: 'Réglages', rows: { pause: 'Pause rencontres' }, count: (n: number) => `${n} liens` },
  en: { title: 'Settings', rows: TODO, count: (n: number) => `${n} links` },
  es: TODO,
  pt: TODO,
  nl: TODO,
});
```

- Le français fixe la forme. Une autre langue a **exactement** les clés du français : une clé en trop ou en moins est
  une erreur de type (et `pnpm i18n:check` le revérifie).
- `TODO` = pas encore traduit : le français s'affiche à la place. Il remplace une valeur, un sous-objet ou une langue
  entière. `pnpm i18n:check` compte les `TODO` ; `pnpm i18n:list` les nomme.
- Un tableau se traduit en entier. Une fonction garde la même signature dans chaque langue.

## Ajouter un texte dans l'app (deux minutes)

1. Ouvre le fichier de ta zone dans `apps/mobile/src/locales/` (`onboarding`, `pet`, `chats`, `rencontres`, `moi`,
   `common`…) ou crée-le pour un nouvel écran :

   ```ts
   // apps/mobile/src/locales/habitudes.ts
   import { TODO } from '@blowy/content';
   import { messages } from './runtime';

   export const habitudes = messages({
     fr: {
       title: [{ text: 'TES\n' }, { text: 'HABITUDES', dim: true }],
       empty: 'Aucune habitude pour l’instant. Choisis-en une, ton minimoa suivra.',
       count: (n: number) => `${n} ${n > 1 ? 'habitudes' : 'habitude'}`,
     },
     en: TODO,
     es: TODO,
     pt: TODO,
     nl: TODO,
   });
   ```

2. Ajoute ta clé dans le bloc `fr`. Si le bloc `en` (ou un autre) liste déjà ses clés, TypeScript te demande d'y ajouter
   `taCle: TODO` : c'est voulu, rien ne se perd entre deux langues.
3. Dans l'écran, rien ne change : `import { habitudes as t } from '@/locales/habitudes'` puis `t.empty`.
   L'objet exporté est « vivant » : il donne toujours la langue courante, même gardé dans une constante du module.
4. Les libellés partagés du domaine (`gaugeLabel`, `formLabel`, `itemLabel`…) s'importent de `@/locales/content`
   (pas de `@blowy/content`, qui ne connaît pas la langue de l'app).

### Règles d'écriture (français)

- Tutoiement, phrases courtes, humour sec plutôt que mignon. Public adulte : pas de ton enfantin, pas d'emoji décoratif
  dans les titres.
- Le personnage est un **minimoa** (un minimoa, des minimoas, « ton minimoa », « le minimoa de Léa »). Jamais « pet »
  dans un texte (les identifiants du code, eux, gardent `pet`). L'app reste **Minimoa**, l'abonnement **Minimoa+**.
- Majuscule en début de phrase. Les grands titres affichés en capitales s'écrivent en capitales dans la source.
- Typographie : apostrophe `’`, guillemets `« … »`, espace insécable (` `) avant `? ! : ;`, à l'intérieur des
  guillemets, entre un nombre et son unité (`3 jours`, `91 %`). `packages/ui` normalise aussi au rendu,
  mais la source reste propre.
- Pas de genre supposé pour la personne : « Tu as mis le nez dehors aujourd’hui ? » plutôt que « Tu es sorti ? »,
  « Léa te fait signe » plutôt que « Léa t’a salué ». Le minimoa, lui, est masculin (« il boude »).
- Un nom propre garde sa casse (`${pet}`, pas `${pet.toLowerCase()}`).

### Nombres, prix, dates

Depuis `@/locales/runtime` (langue de l'app, région du téléphone) :

| Besoin | Fonction |
|---|---|
| Pluriel | `plural(n, { one: 'jour', other: 'jours' })` (règles par langue : en français, 0 est singulier) |
| Nombre | `formatNumber(1234)` |
| Prix | `formatPrice(499, 'EUR')` → « 4,99 € » en France, « €4.99 » en anglais |
| Date | `formatDate(iso, { day: 'numeric', month: 'long' })` (l'anglais de Minimoa est américain : « November 22 », « 5:19 PM », quelle que soit la région du téléphone) |
| Majuscule initiale | `upperFirst(mot)` (un libellé placé en tête de phrase) |

Un prix n'est **jamais** écrit dans une phrase : la phrase est une fonction qui reçoit le prix mis en forme
(`caption: (total: string) => \`Facturé ${total}/an\``). Aujourd'hui les montants viennent de `OFFERS` (domaine) ;
quand les achats seront branchés, ils viendront du magasin.

## Kit d'interface (`packages/ui`)

Aucun texte écrit en dur dans un composant, libellés d'accessibilité compris. Un mot vient en prop, ou du petit
dictionnaire `UiStrings` (`back`, `close`, `add`, `send`, `options`, `percent(n)`, `percentSuffix`, `labelValue(label, value)`) lu avec
`useUiStrings()` et fourni par l'app (`apps/mobile/src/locales/ui.ts`, `UiStringsProvider` à la racine). Un nouveau mot
générique s'ajoute à `UiStrings` puis à `locales/ui.ts`. `pnpm i18n:check` refuse un texte français en dur dans le kit.

## Langue à l'exécution (app)

- `src/core/locale.tsx` lit la langue du téléphone (`expo-localization`) avant le premier rendu, puis la suit
  (`LocaleRoot`) : changement → textes mis à jour sur place, arbre remonté, données de l'API relues.
- L'app envoie la langue à l'API : `Accept-Language` sur chaque requête (client `@blowy/api-client`, option
  `getLocale`), `locale` à l'inscription, et `PATCH /v1/me { locale }` quand la langue du téléphone change ou quand le
  profil a été créé dans une autre (`LocaleBridge`).
- Tester une langue sur le web : la langue du navigateur (Playwright : `browser.newContext({ locale: 'en-US' })`).

## Textes partagés et API (`packages/content`)

Même forme : `defineMessages({ fr, en, es, pt, nl })` dans `packages/content/src/**`, lu avec `.in(locale)`.

| Dictionnaire | Contenu |
|---|---|
| `labels` | pôles, formes, niveaux, événements, 3 mots, soins, objets, accroche |
| `voiceText` (`voice.ts`) | répliques des minimoas dans les liens et les rencontres, bandeaux du système |
| `chatText` (`v7/chat.ts`) | interventions des minimoas dans les chats, accord de lecture, santé des liens |
| `emailText` | e-mails transactionnels |
| `emailChromeText` (`email/chrome.ts`) | habillage des e-mails : bulle du minimoa, étiquette, texte d'aperçu, textes alternatifs des images, pied (mise en page `email/layout.ts`, images `apps/web/public/email`, aperçus `pnpm emails:preview`) |
| `notificationTexts` | titres et corps des notifications, libellés des réglages |
| `apiErrorText` | messages d'erreur de l'API (défaut par code, modules du cœur) |
| `visionText`, `rituelsText`, `facturationText`, `challengeText` | test de vision, rituels (habitudes, défis, bilans), Minimoa+ et modération, défis V6 |

Quelle langue côté API :

- **Réponse à une requête** : la langue de l'app, en-tête `Accept-Language` (`@ReqLocale() locale: Locale` dans un
  contrôleur, `requestLocale()` dans un présentateur appelé plus loin). Sans en-tête : français.
- **Texte envoyé ou rangé pour quelqu'un** (notification, e-mail, réplique de minimoa, bilan de la semaine) :
  `profiles.locale` de cette personne. Une réplique de minimoa est écrite dans la langue de son humain ; les bandeaux du
  système d'un lien, dans la langue de la personne A quand les deux diffèrent (limite connue).
- **Erreur** : `throw new DomainError('invalid', errorText('linkNotFound'))`, ou pour un autre dictionnaire
  `textOf(visionText, (t) => t.errors.locationConsent)`. Le message est résolu dans la langue de la requête au moment
  de répondre. Une chaîne simple reste acceptée mais n'est pas traduite : à éviter.
- **Notification** : passer des données au `Notifier` (date ISO `endsOn`, centimes `price` + `currency`, identifiant
  d'objet `item`) ; `v7/notifications` les met en forme dans la langue de la personne.
- Consignes des modèles d'IA (`CHAT_AI_SYSTEM`, `reviewCoachSystem`, `habitProofSystem`) : en français, stables
  (cache), jamais montrées ; la langue de la réponse est demandée dans le message.
- Garde-fou « toujours positif » du bilan (`isKindText(texte, langue)`, `packages/domain/src/rituels/review.ts`) : une
  liste de mots interdits par langue, appliquée dans la langue de la personne (modèles de phrases et reformulation de
  l'IA). Un nouveau modèle de phrase du bilan ou de la santé d'un lien est vérifié dans les cinq langues par
  `packages/content/src/v7/kindness.test.ts`.
- Monde d'exemple du compte de revue et monde de démo : textes dans `auditText.review` et `auditText.demo`, écrits dans
  la langue de la personne (celle de l'app à la connexion pour le compte de revue).

## Vérifier

- `pnpm i18n:check` (lancé par `pnpm test`) : clés identiques dans les cinq langues, aucun « pet » dans un texte
  français (dictionnaires, écrans, kit, site) ni dans aucune langue du site, aucun texte en dur dans `packages/ui` ; affiche ce qui reste en français
  par langue.
- `pnpm i18n:list` : la liste des clés non traduites, dictionnaire par dictionnaire (point de départ de la passe de
  traduction).

## Site minimoa.app (`apps/web`)

Mêmes cinq langues, même registre (anglais américain, espagnol d'Espagne avec « tú », portugais du Brésil avec « você »
comme l'app, pages légales comprises : tout le portugais de Minimoa est du pt-BR, « celular », « cadastro », « usuário »,
« tela », « acessar », « excluir »). Détail : `apps/web/src/i18n/site.ts`.

- **Textes** : un dictionnaire par zone, `siteMessages({ fr, en, es, pt, nl })` (`content/site.ts`, `public.ts`, `quiz.ts`,
  `growth.ts`, `open.ts`), la landing en un fichier par langue (`content/landing-text/<langue>.ts`, typé par `fr.ts`).
  Pas de `TODO` sur le site : chaque langue est publiée, une clé manquante est une erreur de type, et `pnpm i18n:check`
  revérifie la forme et l'absence de « pet » dans les cinq langues (`content/registry.ts`). Prix : `OFFERS` du domaine
  et `formatPrice` de `@blowy/content`, la phrase est une fonction.
- **Pages indexées** (landing, `/quiz/`, `/quartier/`) : une page statique par langue, français à la racine, les autres
  sous `/en/`, `/es/`, `/pt/`, `/nl/` ; `hreflang` + `x-default`, canonique, `og:locale:alternate`, `sitemap.xml`,
  sélecteur de langue (barre et pied de page). Jamais de redirection selon la langue : une bannière « Available in
  English » au plus.
- **Pages de partage** (`/m/`, `/i/`, `/g/`, `/c/`, `/r/`, `/l/`, `/plus`, `/defi`, `/habitudes`, `/carte`, 404, liens
  `/quiz/<code>` et `/quartier/<zone>`) : une seule adresse, les cinq langues rendues au build et celle du téléphone
  montrée avant les scripts de page (`layouts/Public.astro`, mode `shell` ; `?lang=xx` pour forcer). Les scripts lisent
  la langue dans `<html lang>` (`i18n/client.ts`).
- Un texte de plus : la clé dans le bloc `fr`, puis dans les quatre autres (TypeScript les réclame).

## Ce qui reste hors du mécanisme

- L'administration (`apps/admin`, messages d'erreur de `modules/admin` destinés aux modérateurs) reste en français.
- Les textes système iOS (autorisations caméra, position, photothèque) ont une seule source, `apps/mobile/locales/fr.json`,
  reprise par `app.config.ts` ; chaque langue a son `locales/<langue>.json` (pour l'instant la phrase française : à
  traduire lors de la passe de traduction, jamais inventée). `plugins/ios-release.test.ts` vérifie que les cinq fichiers
  ont les trois mêmes clés et qu'aucune autre autorisation n'apparaît.
- Les écrans de développement (`app/dev/*`) ne sont pas traduits.
